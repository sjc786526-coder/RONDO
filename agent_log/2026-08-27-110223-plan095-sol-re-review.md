## 2. 实现复核

- `cloud_config.rs` 在 `CloudScorerDescriptor::validate` 内同时校验 service descriptor 与 provider，并强制
  `identity.model.model.name() == provider.model`、revision 为 `serving-revision-unverifiable`；公共构造函数不再允许调用方自选 serving
  revision。
- `cloud_scorer.rs` 的请求使用同一个已绑定 model；响应携带 model 时必须等于 requested model，只有 `provider_managed` 模式允许响应完全
  不携带 model。不同 model 继续通过既有 service 边界形成 typed identity mismatch，没有旁路 verdict。
- runtime 在第 `k` 次失败后等待 `backoff × k`；descriptor 校验按
  `timeout × n + backoff × (n−1)n/2` 计算，checked arithmetic 与 `n=2/3/4` 边界测试一致。
- cancellation 由既有 client 断开、service `peer_closed`、request cancellation token 与 scorer `tokio::select!` 贯通；HTTP/retry future
  没有 detached spawn。集成测试在 provider 已收到请求后取消，等待超过该 fixture 未取消时必然发生 retry 的窗口并确认仍只有一次请求，
  随后健康请求成功。active shutdown 测试在请求在途时经过 graceful deadline 触发 force-cancel，得到 typed `ShuttingDown` 并有界退出。
- 独立 cloud service binary 是唯一云端选择入口；既有 trait、service 核心、packet/render、`team_publish` 与本地 worker 未改。未启动 cloud
  binary 时不解析 cloud descriptor、不读取目标 credential、不产生 provider 网络请求；ready 不发送付费探针。
- cloud prompt 使用同一 typed `PublicationPacket` 的 bounded JSON 投影，解析只接受单个有限 `quality` 标量；domain 与 threshold verdict
  仍由既有 service 合同执行。非 2xx 正文不读取，普通日志不记录请求/响应正文或 credential。
