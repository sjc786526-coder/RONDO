### 2.3 publication journal 前失败终态

既有路径在 completed run 后先把 paid pair slot 持久化为 `publishing`，再调用 `ArtifactWriter.finalize()`。
`finalize()` 的 record/tree/secret/index 等确定性校验发生在 journal 创建前；这些校验失败时，旧代码因
`publication_staged=True` 直接抛出，重启又找不到 journal/index record，slot 会永久停在 `publishing`。

最小修改：

- `ArtifactWriter.publication_started()` 只查询 journal 或 target 是否已出现，不新增状态/schema。
- paid CLI 捕获异常时：
  - journal/target 尚未出现：撤销未发布 staging，复用现有 `publish_terminal_bench_failure()` 和
    `sequence.finish(completed=False)`；
  - journal/target 已出现：保持既有 recover-only publishing 路径，不创建第二终态。

生产 CLI 回归注入 journal 前 `ArtifactError`，确认结果为 `infra_failed/publication`、pair finish(false)、无遗留
journal；既有三个 journal/target/index crash-cut 恢复回归保持通过。

### 2.5 harness / measurement checkout 分离

paid CLI 原先同时把 cwd 当成当前 eval harness checkout 和 frozen product measurement checkout。当前 harness commit
晚于 RONDO bundle 的 `cb652e...`，一个 worktree 不可能同时满足“当前 harness clean”与“detached measurement
commit == bundle source”。这会让任何准确命令在 Docker/API 前失败。

CLI 新增 `--measurement-worktree-root`：

- 当前 cwd 仍是 Plan 010 clean harness，供 watchdog/module identity 与 `eval_harness_commit` 校验；
- 参数指向已有 clean detached `.claude/worktrees/0810-p1-measurement`，只供原有 measurement validator 使用；
- 两者必须属于同一 Git common root，measurement 的 detached/clean/manifest source 规则没有放宽。

真实运行还需要同 readiness commit 的独立 results worktree。原因是 slot 1 的 append-only result 会弄脏 results
checkout；若直接写入 harness worktree，slot 2 的 clean-harness preflight 必然失败。这是执行拓扑，不是新 schema。

## 4. 授权后的 canonical 命令

下面整段是后续单独授权后的一次性命令，不在本批执行。它先从 readiness commit 建立独立 results worktree，
随后在同一 clean harness 下由项目 watchdog 严格串行执行 RONDO→Codex；`set -e` 保证首侧失败时不运行第二侧。
两个 metrics 路径、results branch/worktree、pair/budget/run paths 必须在执行前不存在。

> 2026-08-10 执行说明：下面保留的是 v6 当时实际执行的命令，v6 已失败且不得复用。该命令清除
> HTTP(S) proxy，导致当前宿主无法连接官方 endpoint；任何后续新 pair 必须删除六个 `-u ...PROXY` 参数，
> 保留宿主网络环境，并继续设置 loopback `NO_PROXY`。详情见同日 paid execution 日志。

```bash
set -euo pipefail

COMMON=/home/sjc/desktop/RONDO
HARNESS=$COMMON/.claude/worktrees/0810-plan010-b3-m1-paid-readiness
MEASUREMENT=$COMMON/.claude/worktrees/0810-p1-measurement
RESULTS=$COMMON/.claude/worktrees/0810-plan010-b3-m1-results
RESULTS_BRANCH=0810-plan010-b3-m1-results
PY=$HARNESS/eval/.venv/bin/python
WATCHDOG=$HARNESS/mydev/scripts/with-build-lock.sh
R_MANIFEST=$COMMON/eval-data/bin/rondo/cb652e1418e06d53171755963ad9eb8075259ffc-x86_64-unknown-linux-musl-runtime-bundle/manifest.json
C_MANIFEST=$COMMON/eval-data/bin/codex/rust-v0.147.0-be6e8eac029b183056b7e4402879f15d2c85f61b-x86_64-unknown-linux-musl-runtime-bundle/manifest.json

READINESS_SHA="$(git -C "$HARNESS" rev-parse HEAD)"
test -z "$(git -C "$HARNESS" status --porcelain=v1 --untracked-files=all)"
test "$(git -C "$MEASUREMENT" rev-parse HEAD)" = cb652e1418e06d53171755963ad9eb8075259ffc
test -z "$(git -C "$MEASUREMENT" status --porcelain=v1 --untracked-files=all)"
test ! -e "$RESULTS"
git -C "$COMMON" worktree add -b "$RESULTS_BRANCH" "$RESULTS" "$READINESS_SHA"

run_side() {
    side=$1
    run_id=$2
    manifest=$3
    metrics=$4
    test ! -e "$metrics"
    env \
        -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY \
        -u http_proxy -u https_proxy -u all_proxy \
        NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost \
        PYTHONPATH="$HARNESS/eval" \
        RONDO_BUILD_METRICS_DIR="$metrics" \
        "$WATCHDOG" "$PY" -B -m rondo_eval.terminal_bench \
        --side "$side" \
        --batch-id p1-fix-git-b3-m1-v1 \
        --run-id "$run_id" \
        --binary-manifest "$manifest" \
        --docker-host-volume /mnt/c \
        --results-worktree-root "$RESULTS" \
        --measurement-worktree-root "$MEASUREMENT" \
        --timeout-seconds 1800
}

cd "$HARNESS"
run_side rondo 20260810-230000000-tb-rondo-r1 "$R_MANIFEST" \
    "$COMMON/eval-data/build-metrics/plan010-b3m1-v1-rondo"
run_side codex 20260810-230000001-tb-codex-r1 "$C_MANIFEST" \
    "$COMMON/eval-data/build-metrics/plan010-b3m1-v1-codex"

RESULTS_WORKTREE_ROOT="$RESULTS" RONDO_COMMON_ROOT="$COMMON" \
PYTHONPATH="$HARNESS/eval" "$PY" -B -c '
import json, os
from pathlib import Path
from rondo_eval.terminal_bench.pair import assess_m1, load_pair_identity
identity = load_pair_identity()
index = Path(os.environ["RESULTS_WORKTREE_ROOT"]) / "eval/results/runs.jsonl"
records = [json.loads(line) for line in index.read_text().splitlines() if line]
ledger = Path(os.environ["RONDO_COMMON_ROOT"]) / "eval-data/pairs" / f"{identity.pair_id}-paid.json"
result = assess_m1(records, identity, pair_ledger_path=ledger)
print(json.dumps(result, sort_keys=True, separators=(",", ":")))
raise SystemExit(0 if result["m1"] == "passed" else 66)
'
```

该命令不会 pull/build，也不调用本地模型。真实 API key 仍只由严格 loader 从 common-root `.env.local` 静默读取并
仅注入 loopback proxy；命令行和日志中没有 key。
