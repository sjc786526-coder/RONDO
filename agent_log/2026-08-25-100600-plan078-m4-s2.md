# Plan 078 M4-S2 执行记录

## 产品结果

- durable Root cold resume 保留 Session/Root/Team 身份，member 只在真实消费入口按需 reload，均不自动发起 model/API；
  corrupt/incompatible Team snapshot fail-closed，不空建、不换 ID。
- durable 顶层 fork、`/new` 与 slash `/clear` 创建新 Session/Root/空 Team；child `fork_turns=none/all/N` 仅决定
  conversation context，仍属原 Session/Root/Team。纯 display clear 不改身份。
- shutdown/close 复用已有 owner、Session Control 与 Agent graph：已接受 shutdown submission 持续 fence，descendant-first
  失能，失败则保留可定位、可重试 owner。app-server timeout 的 late observer 只在真实 termination 后移除
  pointer-identical owner。
- detach 与 idle unload 分离；零订阅窗口完整计时，unload 失败保持 loaded/retryable，不先丢唯一 owner。
- archive/unarchive/delete 继续走 ThreadStore 冷态域；对 ordered subtree write、live writer、partial failure 和结果未知如实
  报错。delete 先删 Team artifact，确认后再删 Root marker；中断后重试能收敛，坏 Root marker 与存在的
  Team artifact 组合保守保留。

## 终审整改

独立终审首轮发现一项 medium：app-server 的 idle/late shutdown 与 archive/delete complete 路径移除 V2
member owner 时，未清理该 Team 独立的 residency deque。容量为 1 时，同 ID lazy reload 会把残留 ID 当作
protected resident，错误返回 `AgentLimitReached`。

修复把 residency 清理收口到 ThreadManager 所有成功 map removal：在 map write/availability gate 尚持有时，使用
实际 removed `CodexThread` 所属的 `AgentControl` 幂等 forget；exact removal 只在 `Arc::ptr_eq` 确认旧 owner
后执行，不会误清 replacement。现有 eviction/reload 回归尾部新增 app-style exact unload → 同 ID lazy reload，
其配置的 V2 容量精确为 1。同一审查者复验后确认 high/medium/low 均无，077 query read/projection
与 078 lifecycle/write 仍无实质 API 语义冲突。

整改后 `fmt`、`fmt-check` 与 `git diff --check` 通过。最终源码上三条 residency/removal 聚焦回归
`3/3` PASS，`codex-core` clippy 无警告 PASS。clippy 首轮只发现一条 `expect_used`；将逻辑上不可达的
panic 改为同一 map/gate lease 内 fail-closed `false` 后，同范围 clippy 和三条回归都在最终源码上通过。
同一独立审查者最终确认该窄修不重开 finding，high/medium/low 均无。

## 第二轮外部终审整改

外部终审提交 `cd25449` 继续识别出三处真实 lifecycle race：旧 owner shutdown 后仍有同步路径按
ThreadId 清理同 ID replacement；subtree close 的 admission gate 只在 durable Team 启用；idle、archive/delete
与 running-resume timeout 在 late observer 完成前释放 pending closing。三项均按实际调用链确认存在，没有采用新 registry、
事务或审计设施。

整改统一复用现有权威边界：

- `ThreadManagerState::send_op` 随结果保留实际 owner；`InternalAgentDied`、tree close 与 batch shutdown 只退休捕获的
  `Arc<CodexThread>`。`ExactThreadRetirement` 在同一 map write lease 与 availability gate 内完成 map、residency、
  Agent registry 和 generation 收口；Missing/Replaced 整批 fail-closed，不清 replacement。
- non-durable 与 durable AgentControl 均使用同一个 subtree/admission gate。guard 在 descendant snapshot 前取得并跨 shutdown、
  durable Closed edge 和 exact retirement 存活；所有退出路径 Drop 后重开，不改变 durable Root 的 terminal close。
- pending unload 改为 generation token；timeout 调用方把 token 交给 late observer，observer 持有到 exact-owner finalizer
  完成。permit closed、Missing/Replaced 与成功 teardown 均释放本次 token，旧 token 不能清除后继 operation；`turn/start`
  等入口在同一 pending 边界内拒绝 closing owner。
