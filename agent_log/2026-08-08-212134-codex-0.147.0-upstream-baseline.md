# Codex 0.147.0 原始基线构建、全量测试与资源测量

## 范围与环境

- 上游：`openai/codex` 的 `rust-v0.147.0`，commit `be6e8eac34711945bc47d57635f4759f20f08df9`。
- 产品源码未参与本轮测试；测试对象是由官方 tag 导出的本地 scratch source。
- 官方 tag 的 workspace `Cargo.toml` 已为 `0.147.0`，但 `Cargo.lock` 的 135 个 workspace package 仍为 `0.0.0`，无法直接 `--locked` 构建。本轮只把这些 lock 条目机械规范化为 `0.147.0`，规范化后的 lock SHA-256 为 `bc4fe450de929afe82928734f860ca83e5f9dc5f9f1211b0974ea47b57af77ca`。
- `rusty_v8` 使用仓库 `.github/actions/setup-rusty-v8/action.yml` 指定的 OpenAI release 资产；archive 与 binding 均通过官方两行 SHA-256 清单。
- 完整命令语义：`cargo build --workspace --locked`，随后 `just test --test-threads 10`；Cargo/rustc 并发为 6。全程只有一个构建，位于独立 systemd cgroup，并由磁盘、内存、swap、PSI 看门狗采样。

## 构建与测试结果

- workspace build 成功。首次使用官方 V8 资产的增量构建耗时 112 秒；后续缓存检查为 1 秒。
- 全量 nextest 完整结束，未被资源看门狗终止，返回码 100：
  - 14,065 tests run
  - 13,981 passed
  - 83 failed
  - 1 timed out
  - 23 skipped
  - 31 项首轮失败、重试后通过
- Guardian 没有终态失败；`guardian_session_prewarms_and_is_reused_for_first_review::api_key_uses_luna_with_responses_lite` 首轮失败后重试通过，后续 P0 定向验收仍需单独覆盖该路径。
- 这组结果是“原始 0.147.0 + 当前本机环境”的上游参照，不是 RONDO P0 验收结论，也不能把 83+1 直接归因于 RONDO。

## 资源峰值与空间结论

- 项目最终峰值：127,422,697,472 bytes。
- Cargo target 最终体积：126,174,883,840 bytes。
- cgroup 总内存采样峰值：17,637,695,488 bytes。
- 匿名内存采样峰值：8,352,325,632 bytes；匿名+内核不可回收峰值：8,620,105,728 bytes。
- swap 峰值：22,200,320 bytes。
- 宿主最低 `MemAvailable`：15,033,628 KiB；cgroup/宿主 `full avg10` PSI 峰值分别为 0.56% / 0.80%。
- 总内存峰值中相当一部分是可回收文件缓存，不能再用 `memory.current >= 15 GiB` 作为单独停机条件。
- 测量后保留源码、V8 校验资产、日志、指标与摘要，并用 `cargo clean --target-dir <exact scratch target>` 删除 89,334 个可重建中间文件；Cargo 报告回收 129.8 GiB。

## 后续复盘边界

- P0 验收只运行与 Guardian、evidence、config 和 CLI override 直接相关的定向门禁，并在需要本地 mock server 时清理外部代理变量；不得用本轮 83+1 掩盖新的 P0 回归。
- 如果未来要收口“上游 0.147.0 在本机的干净全量基线”，应在隔离 `CODEX_HOME`、隔离 skills、明确代理/no-proxy、固定 cwd、按 release fixture 处理 `0.0.0` 版本语义后另跑一次；本轮不重复执行全量测试。
- 原始证据保存在本机 `.codex/build-study/0.147.0-upstream/`；该目录 git-ignored，不作为远端交付物。
