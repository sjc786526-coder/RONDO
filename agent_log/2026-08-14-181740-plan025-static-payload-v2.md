## 改动

- `eval/rondo_eval/evidence.py`
  - `STATIC_SCHEMA_VERSION` 拆成 `STATIC_PAYLOAD_SCHEMA_VERSION = 2`（静态**输入** payload）与
    `STATIC_DECISION_SCHEMA_NAME = "rondo_static_approval_v1"`（结构化**决策输出** schema，不随动）。
    validator 与 policy identity 一起声明 v2，v1 payload 无法被 v2 sink 接受。
  - 新增 `_neutral_items()` / `_project_reasoning_item()`：`reasoning` 是唯一被投影的 item 形状，
    投影只发生在公共 `build_static_payload()` 内。公开 `summary_text` / `reasoning_text` / `text`
    按 wire 顺序原样转成一条 `message(role=assistant, content=[output_text…])`；无公开内容的 item 删除；
    未知字段、非法子类型、非字符串文本、非数组 `summary` 等一律 fail-closed。
    `encrypted_content` 与 provider session `id` 不进入 payload。
  - `_reject_private_transport()` 增加两条终端拒绝：残留 `type=reasoning` 与任何 `encrypted_content`。
- `eval/rondo_eval/local_approval/client.py`：错误文案与 builder docstring 对齐 v2，
  `response_format` 的 schema name 改用共享常量（值仍是 v1，不动 qualification evidence）。
- 测试：evidence 侧新增 v2/v1 边界、encrypted-only 删除等价于不存在、公开文本按序投影、11 种畸形形状
  fail-closed，并把 reasoning 与 `encrypted_content` 回流补进既有终端 validator 用例；
  client 侧新增一条“出站请求已投影且无私有运输”；census 侧新增一条逐字节相等回归。
- 文档：Plan 025 当前状态、`doc/WBS.md`、`doc/WBS/local-approval-model.md`、`doc/WBS-COMPLETED.md`。

## 关键判断

- **拒绝原因确认**：只读冻结 b10333 源码（`tools/server/server-chat.cpp`）显示，其 Responses adapter 对
  `type=reasoning` 强制要求 `content` 是非空数组，因此归档里 24 个 `summary:[] + encrypted_content` 的 item
  必然 400；同一文件也显示 assistant + `output_text` 是它接受的输入形态。中立消息形态据此选定，
  而不是猜一个形状。
- **不做通用 recursive scrub**：先按已知字段白名单理解 item，再决定删除或投影，避免未知形状被静默吞掉。
- **删除等价于不存在**：encrypted-only item 被移除后的 canonical bytes 与该 item 从未出现时逐字节相同，
  这条比单纯断言“没有 reasoning 字样”更能说明投影没有顺带改动其他证据。
