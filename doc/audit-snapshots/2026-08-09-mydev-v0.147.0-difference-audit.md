## 2. 总结：实际产品增量

当前 `mydev` 并不是另起一套 Codex CLI 或 Agent Harness。它可以概括为：

> 冻结 Codex CLI v0.147.0 + Guardian 审批模型/effort 覆盖 + 可选 `E_final`
> 本地证据包 + MCP OAuth 的无浏览器登录选项 + 测试和本机构建设施强化。

尚未落地为当前产品能力的事项包括：Terminal-Bench 测评链路、离线回放测评、
Harness 性能优化、本地审批 provider 切换/本地模型服务、共享多智能体证据链。

相对前一审计源快照，第二批改动只强化 OAuth、SSE、Landlock 和 V8 的测试合同；
没有新增用户可见的 CLI 参数、配置、provider/runtime 能力或 release Rust API。
下文的产品增量结论因此保持不变。

### 2.1 Guardian 显式模型、推理强度与证据目录

`[auto_review]` 增加三个配置字段：

```toml
[auto_review]
model = "..."
reasoning_effort = "..."
evidence_dir = "/private/path"
```

涉及的实现路径：

- `codex-rs/config/src/config_toml.rs`
- `codex-rs/core/src/config/mod.rs`
- `codex-rs/core/config.schema.json`
- `codex-rs/core/src/guardian/mod.rs`
- `codex-rs/core/src/guardian/review.rs`
- `codex-rs/core/src/guardian/review_session.rs`
- `codex-rs/core/src/client.rs`
- `codex-rs/core/src/guardian/evidence.rs`（新增）
- `codex-rs/core/upstream-source-baseline.toml`（新增）
- `codex-rs/thread-manager-sample/src/main.rs`（补齐 `Config` 初始化）

语义：

- `[auto_review].model` 的优先级是：显式配置 > model catalog 的
  `auto_review_model_override` > provider 默认 Guardian 模型。
- `reasoning_effort` 只有在配置时才覆盖根据模型能力推导的默认值。
- 该配置只覆盖模型 slug。Guardian 继续继承父会话的 provider 和 base URL，因而
  不能把它表述成“已可切换到本地 provider”。

### 2.2 Guardian `E_final` 审批证据包

新增的 `core/src/guardian/evidence.rs` 是唯一新增的非测试 Rust 实现文件。
未配置 `evidence_dir` 时，它完全关闭；配置后每轮 Guardian 审批会写：

```text
<evidence_dir>/<review_id>/E_final.json
<evidence_dir>/<review_id>/meta.json
```

其行为边界：

- 在 HTTP 与 WebSocket 的实际 transport send point 前捕获完整逻辑 Responses
  请求；不是 WebSocket delta。
- 仅接受已绑定 Guardian session 且 `request_kind == turn` 的请求；prewarm、
  compaction、memory 等请求不能覆盖证据。
- 重试保留最后一次实际发送尝试；若本轮从未发送，则只落盘
  `evidence: none` 的 `meta.json`，不会借用旧请求。
- 会移除不稳定的 transport 字段、response item `id` 及 provider-private 的
  `encrypted_function_args`，并仅在输入项的结构位置稳定重映射 `call_id` 与
  `turn_id`。这不是对文本内容的全面脱敏。
- `E_final` 可能包含 task context 和 policy，属于原始本地记录。Unix 下目录与
  文件分别设置为 `0700` / `0600`，以原子写入发布。
- 写盘失败只记录 warning，绝不改变 Guardian 的允许/拒绝决定。
- `meta.json` 记录冻结上游 tag/commit；这只是 source identity，不代表有效 policy
  已被哈希固定。

### 2.3 MCP OAuth 无浏览器登录

新增 CLI 形态：

```text
codex mcp login <server> --no-open-browser
```

涉及：

- `codex-rs/cli/src/mcp_cmd.rs`
- `codex-rs/rmcp-client/src/lib.rs`
- `codex-rs/rmcp-client/src/perform_oauth_login.rs`
- `codex-rs/core/src/mcp_skill_dependencies.rs`

该开关仍会打印授权 URL、启动 callback listener、等待回调、换取并持久化 token；
唯一区别是不会调用系统浏览器。首次 OAuth 与 scopes 被拒后去掉 scopes 的重试都
会透传同一选择。第二批将此 retry 提炼为私有可注入 seam，并以真实两轮 retry
覆盖证明 `--no-open-browser` 在两轮都保持 `Disabled`；这不是新增登录能力。

新增公开 `BrowserLaunch::{Enabled, Disabled}`，并使公开 Rust API
`perform_oauth_login(...)` 多一个必传参数。因此这也是对外部 Rust 调用者的一项
签名兼容性变化。默认 CLI 登录、`mcp add`、session 内依赖登录及 silent wrapper
仍显式保持 `Enabled`；`perform_oauth_login_return_url` 保持 `Disabled`。

### 3.1 `OutboundProxyPolicy::Direct`

以下路径新增 `#[doc(hidden)] OutboundProxyPolicy::Direct`：

- `codex-rs/http-client/src/outbound_proxy.rs`
- `codex-rs/http-client/src/route_aware_client_pool.rs`
- `codex-rs/core-plugins/src/startup_sync/http_client.rs`

它用于跨 crate 测试直连：不读取 PAC/WPAD、系统代理或
`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`NO_PROXY`，最终使用 reqwest `.no_proxy()`。
生产配置解析、CLI、app-server/wire schema 与常规 `Config::http_client_factory()`
仍只会选择既有 `ReqwestDefault` 或 `RespectSystemProxy`。

它不是用户可配置的“关闭代理”功能；但它是一个公开 enum 的新增 variant，外部 Rust
消费者若有穷举 `match OutboundProxyPolicy`，需要增加该分支。
