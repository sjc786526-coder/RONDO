关于性能测评设施“
建议将 RONDO 的性能测评设施划分为两个层级：第一层是**内核级性能测评**，作为日常优化的主要量化依据，沿用 Codex 已有的 Divan 与 Bazel benchmark 基础设施，补充确定性的组件 benchmark 和轨迹重放测试，在固定输入、固定模型事件和固定工具结果的条件下，分别测量流式事件解析、上下文构建与压缩、工具调度、Shell 执行、事件队列、会话持久化、取消恢复等关键路径的延迟、吞吐、CPU、内存分配、峰值内存和资源清理能力；Codex 自带的常规 Rust 单元测试和集成测试仍归入正确性与回归测试，不计入性能测评结果，但仓库中已有的 Divan benchmark 和 Bazel 端到端 macrobenchmark 可以直接纳入该层并逐步扩展。第二层是**端到端性能测评**，使用 Harbor 统一运行冻结版本的 Terminal-Bench 2.1 任务子集，对比 Codex `rust-v0.146.0` 基线与 RONDO 候选版本，在固定模型、推理参数、权限、容器、时间和 token 预算的条件下，记录任务成功率、配对胜负、负向翻转、token/成功任务、耗时/成功任务及 Harness 故障率；该层主要验证多项内核优化累积后是否改善真实 Agent 能力和运行效率，并作为非退化与最终验收手段，而不承担细粒度内核性能归因。

关于测试体系：
建议直接继承并扩展 Codex 原有测试体系，不另建独立框架：原则上保留全部上游测试作为兼容性基线，复用其 Nextest、`TestCodexBuilder`、WireMock、临时 workspace、exec-server、app-server 测试客户端及 Divan/Bazel benchmark等测试设施；RONDO 只为新增模块、改变后的行为和新性能路径补充增量单元测试、集成测试与基准测试。但是对行为型优化，保留仍有效的原测试，修改已经不再成立的旧语义测试，并且需要性能测评的证据证明行为优化有效；对修复 bug 的优化，原测试保留，新增一个旧实现失败、新实现通过的回归测试。纯实现优化原则上不修改原测试，性能测评交给测评设施。
