# 方向 1 前置：教师 harness 只读研究

最后更新：2026-08-08 ｜ 依赖：无 ｜ 当前 Codex 基线：`v0.147.0` ｜ 顶层路线见 `doc/WBS.md`

## 定位

方向 1（Terminal-Bench 2.1 成功率优化）的**实施**被测评基线阻塞，但"看别人怎么做"不需要任何前置。本轨现在并行开跑，**只出文档，不写一行功能代码**，目标是在测评基线就绪那天手上已经有一份排好序的优化候选清单。

研究对象：`reference-agent-harness/` 下的 `claude-code`、`kimi-code`、`opencode`、`openhands-sdk`。

## 硬约束（重要）

- **只读**：不修改 `reference-agent-harness/`，不向 `mydev/` 写任何来自本轨的功能代码。
- **只学思想，不搬代码**：参考实现的许可证状况不一，一律以"机制描述 + 自主重写"的方式落地，禁止复制粘贴源码或逐行翻译，避免许可证污染。清单里记录的是设计要点，不是代码片段。
- 不做收益承诺：清单里的收益预估是待验证假设，最终只认测评数据。

## 任务分解

### T1 主题化通读（规模 M）

按主题横向对比四套实现，而不是逐个仓库写读后感。主题至少覆盖：

- 上下文管理与压缩策略（何时压、压什么、保留什么）
- 工具集设计（粒度、命名、参数形态、错误回传格式）
- 子智能体与并行任务的切分与汇合
- 计划机制与自纠错（重试、回退、卡死检测）
- 终止判据（何时认为任务完成 / 无望）
- 系统提示与指令层级的组织方式
- 沙箱、权限与审批的介入点

产出：`doc/` 下一份主题对比笔记（一份，不按仓库拆四份）。

### T2 与冻结 codex `v0.147.0` 的对照矩阵（规模 M）

- 逐主题标注：codex 现在怎么做、教师们怎么做、差异是什么、差异是否可能影响 Terminal-Bench 成功率。
- 明确区分"codex 有意为之的设计"和"codex 的真实短板"，不把风格差异当缺陷。

### T3 候选优化点清单（规模 S）

每条候选记录：

| 字段 | 说明 |
|---|---|
| 机制描述 | 要改什么，改成什么样 |
| 类型 | 行为保持型 / 行为改变型 / bug 修复型 |
| 所需测评轨 | 行为保持型走离线回放，行为改变型必须走真实 TB 跑批 |
| 预期收益 | 待验证假设，注明依据 |
| 风险与影响面 | 涉及模块、可能破坏的既有测试与行为 |
| 实施规模 | S / M / L |
| 优先级 | 收益/成本/风险综合排序 |

产出：清单文档，按优先级排序，作为 P4 阶段的输入队列。
